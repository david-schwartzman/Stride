# /refresh-indexes

Rebuild every `index.yml` under `softwareos/` from the filesystem, which is the **source of truth**. The index files are generated, refreshable views — never authoritative. Run this after editing folders by hand, or whenever the indexes drift from what's on disk.

This command is read-only except for the three index families it (re)writes. It never creates, moves, or deletes any product/epic/spec folder.

## Locating SoftwareOS

1. Run `git rev-parse --show-toplevel` to find the repo root. If `<root>/softwareos/` exists, that's the SoftwareOS root. Otherwise walk up from the current directory looking for a `softwareos/` folder.
2. If no `softwareos/` is found, tell the user to run `/join-project` (existing codebase) or `/plan-customer` (new customer), or the installer, and stop.
3. Read `softwareos/config.yml` for `customer` and `default_branch`.
4. **Enumerate everything from the filesystem — never from a cached index.** The whole point of this command is to regenerate the caches from disk.

## What to scan

From `softwareos/`, enumerate on disk:

- **Products** — immediate subdirectories of `softwareos/products/`.
- **Epics** — for each product, subdirectories of `softwareos/products/<slug>/epics/`.
- **Specs** — for each epic, subdirectories of `.../epics/<epic>/specs/` (these are `YYYY-MM-DD-<slug>` folders).

Read each entity's metadata from its primary doc's header lines (the `> Key: value` convention used across SoftwareOS):

- **Product** — display `name` from a `> Name:` line in `products/<slug>/mission.md`; `repos` from the comma-separated `> Repos:` line in `products/<slug>/mission.md` (the `repos.md` table is the human-readable mirror); `status` = `documented` if `mission.md` exists, else `planned`.
- **Epic** — `name` from the H1 title of `epics/<epic>/epic.md`; `status` from its `> Status:` line (`planning | active | done`, default `planning`).
- **Spec** — `slug` = the spec folder name minus the `YYYY-MM-DD-` date prefix; `status` from `spec.md`'s `> Status:` line (`shaped | in-progress | done`); `branch` from its `> Branch:` line; `covers` from its `> Covers:` line, comma-split and trimmed. **Treat any of these as empty:** the line is missing entirely, or the value is `—` (em-dash — the canonical form written by `/shape-spec`), `-` (hyphen), `none` (case-insensitive), or a whitespace-only string. This guards against a hand-typed `-` parsing as a claim on a path literally called `-`. Each real entry is a route (`/checkout/guest`), a path glob (`src/features/checkout/**`), or a path/module (`src/lib/pricing.ts`). De-dupe, preserve source order, and keep case as written.

If an epic folder has no `epic.md`, or a product folder has no `mission.md`, still index the folder but note the gap in the report.

## The three index formats (authoritative)

Write these exact shapes. Every file begins with the generated header verbatim. Use today's date (`date +%Y-%m-%d`) for `generated:`. List products, epics, and specs **alphabetically by slug**. `epic_count` / `spec_count` reflect the folders on disk.

**`softwareos/ecosystem/products.index.yml`**
```yaml
# Generated by /join-project or /refresh-indexes — do not hand-edit; rebuild with /refresh-indexes.
generated: <YYYY-MM-DD>
customer: <customer-slug>
products:
  - { slug: <slug>, name: <Name>, docs: products/<slug>/, repos: [<repo>, <repo>], status: <planned|documented>, epic_count: <n> }
```

**`softwareos/products/<slug>/epics.index.yml`**
```yaml
# Generated by /join-project or /refresh-indexes — do not hand-edit; rebuild with /refresh-indexes.
generated: <YYYY-MM-DD>
product: <slug>
epics:
  - { slug: <epic-slug>, name: <Name>, status: <planning|active|done>, spec_count: <n>, path: epics/<epic-slug>/ }
```

**`softwareos/products/<slug>/epics/<epic>/specs.index.yml`**
```yaml
# Generated by /join-project or /refresh-indexes — do not hand-edit; rebuild with /refresh-indexes.
generated: <YYYY-MM-DD>
epic: <epic-slug>
specs: []   # entries: { folder: <YYYY-MM-DD-slug>, slug: <slug>, status: <shaped|in-progress|done>, branch: <branch>, covers: [<route|path|glob>, ...] }
```
(When specs exist, replace `[]` with one entry per spec folder.)

`covers` is **always present** on every entry, so readers (`/shape-spec`'s pre-flight check and `/spec-of`) never have to special-case a missing key. When it is empty, emit `covers: []` inline; when it is non-empty, emit block form for readability:

```yaml
specs:
  - folder: 2026-07-30-guest-checkout
    slug: guest-checkout
    status: shaped
    branch: feat/checkout-booking-flow/guest-checkout
    covers:
      - /checkout
      - /checkout/guest
      - src/features/checkout/**
  - { folder: 2026-08-02-payment-retry, slug: payment-retry, status: shaped, branch: feat/checkout-booking-flow/payment-retry, covers: [] }
```

## Write + report

1. For each index file, compare the regenerated content to what's on disk; write only if it changed (ignore the `generated:` date line when deciding "changed", so an unchanged tree reports zero writes).
2. Always ensure the top-level `softwareos/ecosystem/products.index.yml` exists (create it, seeded empty, if the tree has no products yet).
3. Print a concise report:
   - `indexes written: <n>` and `unchanged: <n>`
   - counts: `<products> products · <epics> epics · <specs> specs`
   - **ownership map coverage:** `<k>/<total> specs have a non-empty covers:` — count specs whose resolved `covers` (after applying the empty-value rules above) is a non-empty list. If `k < total`, add a second line naming the gap so drift is visible instead of silent: `<total - k> specs have no covers claim — /spec-of will not find them, and /shape-spec Step 4 cannot warn about overlap on their areas`. If the tree has zero specs, omit this section entirely (nothing to report).
   - anomalies, one per line: epic folder without `epic.md`, product folder without `mission.md`, spec folder without `spec.md`, spec folder whose `spec.md` has no `> Covers:` line (legacy spec — emit `covers: []` and flag it so it can be backfilled).

Never touch anything but the three index families.
